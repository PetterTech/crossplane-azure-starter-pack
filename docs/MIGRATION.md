# Migration from the javazone and nic branches

`main` starts clean from the initial commit (`LICENSE` only) and is rebuilt as three Crossplane projects (`foundation`, `services`, `landingzone`) under `projects/`. Nothing from the old branches is copied verbatim. This page maps what each old branch contained to what happened to it.

The old content stays untouched on `origin/javazone` (aa43faa) and `origin/nic` (bb3e866) as history. The Azure bootstrap scripts (`Crossplane/Deploy.ps1`, `Crossplane/infrastructure/*.bicep`, `Crossplane/kubernetes/*`) exist only in earlier history of a local `javazone` branch (for example commit 540edb2) and never reached `origin/javazone`.

## Dropped

| Item (branch) | Reason |
|---|---|
| Bicep templates `aks.bicep`, `crossplaneIdentity.bicep`, `main.bicep` and `Deploy.ps1` (local javazone history) | Cluster and identity provisioning is the adopter's responsibility. The platform ships `setup/` templates and documents identity bootstrap in `docs/identity-bootstrap.md`. |
| `Crossplane/kubernetes/*` demo manifests, `crossplane-values.yaml`, `provider-azure-storage.yaml`, `provider-family-azure.yaml` (local javazone history) | Demo wiring for one event cluster; replaced by `setup/providers.yaml`, `setup/functions.yaml` and `setup/deployment-runtime-config.yaml`. |
| `crossplane/provider-config.yaml` and `crossplane/service-account.yaml` (javazone) | Contained real subscription/tenant/client IDs. Replaced by `setup/` templates and per-subscription identities generated by the Subscription API. |
| `examples/crd-storage-account.yaml`, `examples/crd-storage-account-simple.yaml` (both) | Raw managed-resource examples, not platform API. Examples are written against the platform XRDs. |
| PrivateEndpoint managed resources (no standalone PrivateEndpoint XRD exists; used inside the keyvault and storage compositions on both branches and containerapp on nic) | The new design creates them conditionally via function-kro, only when networking is private. |
| `providerConfigName` / `providerConfigKind` fields on all XRDs (both) | Provider configuration is not user-facing. The Subscription API selects the namespaced ProviderConfig. |
| `platform.example.org` API group (both) | Renamed to `platform.a5n.io`. |
| Event-specific defaults: `rg-javazone`, `pool-javazone`, `rg-nic`, `pool-nic`, MG `NIC`, `quickstart:latest` image default (both) | Replaced by EnvironmentConfig keys (`docs/environment-contract.md`). |
| Hard-coded GUIDs and IDs in examples and defaults (both) | Values come from the EnvironmentConfig or the XR. |
| Demo-only docs and CI | None exist on the two remote branches. No demo-only docs or CI are carried over. |
| Provider pins `v2.7.1` (both) | Reconciled to the `v2.8.0` family pinned in `setup/providers.yaml`. |
| `provider-azure-containerapp` for anything except ContainerApp | Kept only for ContainerApp. |

## Kept or redesigned

| Item | Where it goes | Status |
|---|---|---|
| StorageAccount, KeyVault, VirtualNetwork definitions and compositions (nic version) | `projects/services`, `projects/foundation` | Rebuilt; see `docs/apis/` |
| ContainerApp (nic only) | `projects/services` | Rebuilt; see `docs/apis/containerapp.md` |
| LandingZone | `projects/landingzone` | Rebuilt; takes a typed `virtualNetwork` reference, see `docs/apis/landingzone.md` |
| Subscription vending | `projects/foundation` | Rebuilt; redesigned around a user-assigned managed identity, the EnvironmentConfig and three bootstrap identities |
| `function-go-templating` pipeline steps (nic: 15 pipeline steps, 4 of them go-templating, one each in containerapp, keyvault, storage, vnet; the nic subscription composition uses patch-and-transform + auto-ready) | patch-and-transform where possible, function-kro for conditional resources | Those 4 steps migrate away as their compositions are rebuilt; the pack keeps exactly one go-templating step, the shared subscription resolver (exception E6) |
| `function-patch-and-transform` v0.8.2, `function-auto-ready` v0.5.0, `function-go-templating` v0.11.3 | `setup/functions.yaml` | Kept, bumped to the versions pinned there |
| Demo app image `ghcr.io/pettertech/demo-app` | ContainerApp examples | Replaced by the brand example image `ghcr.io/pettertech/hello-api` |

The old files remain available only through the old branches; nothing on `main` references them.
