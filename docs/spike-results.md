## Decisions that need Petter's input

1. **Pipeline order**: environment, kro, resolver, P&T, auto-ready (plan said resolver before kro; disproven).
2. **Resolver**: keep the go-templating resolver (fail-closed, retains resources) or go kro-only (fail-open: deletes composed resources when the lookup goes empty).
3. **function-extra-resources**: drop it in favour of go-templating's built-in ExtraResources (templated namespace, no cross-namespace leak).
4. **Subscription discovery label**: a function cannot stamp it. Choose who labels it (vending tooling / platform), or resolve without the label.
5. **Orphan semantics**: express as `managementPolicies` because `deletionPolicy` does not exist on `.m` MRs.
6. **Status write-once CEL rule**: adopt it, accepting recover-by-delete.
7. **Tiering**: per distinct package only; same package twice is impossible.
8. **Unresolved XRs**: auto-ready yields Ready=True with zero composed resources. Choose an explicit not-ready mechanism. Also, kro status keys must be declared in the XRD.
9. **Silent missing ProviderConfig**: decide on a monitoring or admission check.
10. **Fix** the `setup/environmentconfig.yaml` comment about function-kro; plan provider version 2.7.1 vs tested 2.8.0.
